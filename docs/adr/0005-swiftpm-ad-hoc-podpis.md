# 0005. Swift Package и ad-hoc подпись, без Xcode-проекта и нотаризации

## Контекст

Приложение должно быть бесплатным целиком, включая сборку (R06, R07.1). Платный Apple Developer аккаунт пользователю не нужен и противоречит замыслу.

## Решение

Проект — Swift Package: библиотека с логикой и исполняемый файл. `scripts/build-app.sh` собирает `.app` с ad-hoc подписью, `scripts/make-dmg.sh` делает `.dmg`. Подписи Developer ID, нотаризации и автообновления (Sparkle) нет.

## Почему

- Подпись Developer ID и нотаризация отвергнуты: нужен платный аккаунт, а «бесплатное» — центральное требование.
- Автообновление Sparkle отвергнуто: ему нужны сервер обновлений и подпись. Обновление — это новая сборка с GitHub.
- Xcode-проект отвергнут: его сложнее хранить в репозитории и собирать одной командой, а SwiftPM воспроизводится без него.

## Последствия

- macOS показывает предупреждение при первом открытии. README обязан объяснять «правый клик → Открыть» и снятие карантина.
- Ad-hoc подпись меняется от сборки, поэтому после каждой пересборки разрешения (микрофон, ввод) придётся выдавать заново. Это неприятно и для разработчика, и для пользователя.
- Пользователи получают обновления вручную.
- Всё, что требует Xcode-специфики (например, некоторые настройки Info.plist и entitlements), приходится делать самими скриптами.
